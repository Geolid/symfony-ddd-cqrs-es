## Source

### Rules

**ALWAYS**
- An event's persisted shape evolves via an upcaster — never retroactively.
- Aggregate: private constructor; creation is a named static factory doing only `new self()` + `recordThat()`; state mutates exclusively inside `#[Apply]` methods.
- `recordThat()` carries a Value Object directly on a Domain Event field once the transition already holds one for that concept — the hydrator reconstructs it via reflection on replay, its invariant never re-runs. A Command/Query/Integration Event field carries that same VO's data as a primitive instead (e.g. `toString()`), independent of the message boundary. A `\DateTimeImmutable`/backed enum stays typed as-is everywhere, never pre-formatted to a string. `#[Apply]` reads a VO field directly; a Command/Query/Integration Event's receiving side rebuilds it through its named constructor (`fromString()`, `::from()`...).
- An event field carrying personal data is tagged `#[SensitiveData(fallbackCallable: ...)]`, plus one `#[DataSubjectId]` field on the same event.
- Autowiring only loads `Domain/Repository/` and `Domain/Service/` — anything else in `Domain/` is never registered as a service.

**NEVER**
- Rename a `#[Event]`/`#[Aggregate]` string identifier without an upcaster in the same change — existing streams become undeserializable on replay.

### Conventions
- A transition's self-guard is decided by outcome: still matches the caller's intent → no-op; no business meaning on current state → throw. A guard against a cross-cutting terminal state (not that transition's own re-entry) stays only while some legitimate caller could still reach the transition despite it — once every call already passes a boundary that continuously excludes that state, drop the guard entirely. A guard against re-entry (redelivery of the same trigger) always stays.
- A cross-aggregate invariant (same BC) is never resolved by loading the gating aggregate separately from the calling Handler — two independent Repository loads share no concurrency control. Tolerates a stale answer → resolved at the Application boundary from a local Finder before the transition is attempted. Must hold exactly at transition time → the two concepts share one aggregate and one stream instead; the guard reads state already on `$this`, never a second Repository call.
- A check computable purely from the candidate value (deterministic) is a Domain-owned port injected into the transition it gates. A check depending on an outside-world fact (can differ tomorrow for the same candidate) never enters a transition — resolved once at the Application boundary before the transition is attempted.
- A business failure is a `final` exception under `Domain/Exception/`, extending `\DomainException`; exposed via a DM through an entry in `config/packages/exceptions.php`; named static constructor, no public constructor. A shape common to every BC is the `abstract Shared\Domain\Exception\AggregateNotFoundException`, mapped once; its sibling `abstract AggregateAlreadyExistsException` follows the same shape, for an aggregate whose creation must reject a second attempt at an identity already taken. Each BC's `final` concrete exception extends the relevant abstract under its own `Domain/Exception/`.
- Naming a static constructor: a single nameable fact gets a specific class + `for*` (`forId`); a failure depending on state gets a category class + `cannot<Verb>`.
- A Value Object is `final readonly`; private constructor enforces invariants (`Webmozart\Assert`); a named constructor (`fromCents`, `fromString`...) validates the input shape. Each stored field is `public readonly` directly — never a wrapper getter. It always exposes `equals()`. A method stays only for `equals()`, a value genuinely computed from 2+ stored fields, or an operation producing a new instance of the VO itself. `toArray()` earns its place once a uniform shape recurs across 2+ call sites (key-for-key unvarying) — a differently-shaped export still maps by hand. `fromArray()` stays forbidden — reconstruction always goes through the named constructor.
- A Value Object lives in the owning BC's `Domain/ValueObject/`; it moves to `Shared\Domain\ValueObject` (its `Valid<X>` compound to `Shared\Application\Validation`) only once a second BC genuinely shares the same concept and invariants — never for validation-compound convenience.
- A literal a VO's own invariant checks, needed elsewhere too (a generator, a fixture), is a `public const` on the VO — never duplicated as a raw literal.
- A same-call comparison parameter for a value existing in two states (raw/derived), untyped, names each side by its state; a stored field keeping only one state names the bare concept, never the state. A VO-typed parameter needs no qualifier.
- Native `\assert()` narrows a value already guaranteed correct by the calling code, never external/user input. `Webmozart\Assert` is reserved for a real invariant that must hold in production and throw a catchable exception.
- A closed-vocabulary lifecycle enum folded from events (`Domain/ValueObject/<X>State`) is suffixed `State`, never `Status` — `Status` names its separate Application-side read/UI value space, never proxying `State`'s case values.
- A business rule reusable and isolation-testable as `isSatisfiedBy(candidate): bool` is a `Domain/Specification/<Name>Specification`, `final readonly` — one genuine reusable predicate already qualifies, composability isn't the bar. BC-scoped, promoted to `Shared` only once a second BC genuinely adopts the same mechanism. A full transition graph belongs on the Aggregate (`private const TRANSITIONS` map keyed by the enum's own `->value`, never a hand-typed literal), never on the `<X>State` enum itself. Formalizing a graph as a Specification is decided by whether its own topology needs to be legible as one artifact — real branching (several edges from the same state), or a chain of 3+ states even unbranched (the full lifecycle then earns being read as one artifact rather than reconstructed from a guard scattered per transition). A two-state toggle never earns it alone — a single bare predicate already reads as clearly. Never decided by whether the calling transition throws or no-ops on failure — that stays the Aggregate's own separate decision, made after the Specification has answered the adjacency question alone.
- An equality check against one enum case is a bare `is<Case>(): bool` on the enum itself, never a Specification. A `TRANSITIONS` map traversed transitively (2+ hops) for reachability must stay acyclic. A map containing a genuine cycle is only ever consumed through single-hop adjacency or `is<Case>()`, never a transitive-reachability Specification.
- A field on an aggregate — and its accessor — earns its place by: a self-guard reads it, or the accessor serves a sibling invariant guard, an outbound port call, or an Integration Event's construction. Never a DM or a test reading business state for display — that goes through a Finder instead, even right after a write through that same aggregate. The accessor is `public private(set)` exposing the field directly — never a wrapper getter; a method stays only where reading it requires real computation beyond the stored value. A fact none of these read back belongs on the event/a Read Model, not as aggregate state. Two facts always evaluated together collapse into one field; two facts a guard needs distinguished stay separate, each shaped by its own cardinality (bool for binary, enum for multi-case).
- `#[Aggregate('<subdomain>.<bc>.<aggregate>')]`, three segments even when the aggregate shares its BC's name; `#[Event('<subdomain>.<bc>.<aggregate>.<past-tense verb>')]` — same prefix plus the verb. The aggregate segment is always its own literal name. The event's PHP class name is prefixed by that aggregate name, or by a Ubiquitous Language term when the aggregate's own name would misdescribe or stutter against the verb — that substitute term stays identical across every event on that aggregate, never chosen per event.
- A BC hosting 2+ aggregates is named after the capability/process it serves, never after one of its own aggregates. A nested aggregate stuttering against its BC folder (matches it exactly, or embeds it as a meaningless prefix/suffix) gets the BC renamed instead of a special-cased folder layout — unless dropping the shared word would lose real distinguishing meaning about that aggregate.
- A `Domain/ValueObject/<X>UniqueKey` enum's case value is prefixed `<subdomain>.<bc>.<aggregate>.`, same three segments as `#[Aggregate]`/`#[Event]`, unconditionally — even when the aggregate shares its BC's name.
- An `#[Apply]` method is `apply<Event>`, `<Event>` being the event's own class name with its aggregate-name prefix dropped — never a short unrelated verb, never the full un-trimmed name. Follows the same Ubiquitous Language substitution as the `#[Event]` rule when it applies.
- An aggregate root ID implements `AggregateRootId` via `Shared\Domain\UuidTrait` — private constructor (`Assert::uuid`), `fromString`, `equals`, `toString`; no `generate()` anywhere. An id is always either supplied externally (a driving DM mints it before dispatch, carried as a plain string on the Command) or computed deterministically — minting fresh inside a Handler/Policy is never idempotent under redelivery. Deterministic derivation from a parent id gets its own named `for<Concept>()` factory on the class (`Uuid::uuid5()` against a private namespace constant) — the same mechanism a Policy creating an aggregate from another's event must use, so redelivery recomputes the same id and a downstream `has()` guard catches the duplicate. A derived id also makes "at most one X per parent" automatic — the store itself rejects a second stream at the same id, with no extra mechanism. Moving an id from derived to externally-supplied removes that invariant along with the derivation: check whether a real business rule (not just the derivation's side effect) actually depended on it, and if so re-provide it explicitly (typically a uniqueness-registry reservation) in the same change — never left for later. An identity that only *references* another aggregate/BC never uses `UuidTrait` — it's a plain string. An identity intentionally reusing another aggregate's own id value unchanged implements `AggregateRootId` through its own standalone implementation — never forced onto `UuidTrait::fromString()` implying a `for<Concept>()` hash it never performs; its `toString()` stays the sole accessor, never a companion property alongside it.
- A reference to another BC's identity inside an aggregate is a plain `string`, never a local VO duplicating that BC's concept.
- Erasure of personal data is crypto-shredding, resolved locally: every aggregate carrying its own `#[DataSubjectId]`-tagged PII owns dropping its own cipher key, keyed by its own subject id (its own root id, or a `for<Concept>()` id derived from a parent identity) — via a dedicated `#[Processor]` reacting to that same aggregate's own `<X>Erased` event, never a `#[Policy]`: dropping a cipher key carries no business meaning of its own. A dependent aggregate erasing on a foreign BC's own erasure reacts to that foreign `<X>ErasedIntegrationEvent` the same way, still dropping its own subject id — never relying on the foreign BC's own drop to implicitly cover it. A projection materializing personal data in clear text isn't covered by any key drop — it redacts on erasure (a targeted update) or gets rebuilt by replay.
- Reusing a foreign BC's own subject id value as a local `#[DataSubjectId]` (instead of the local aggregate's own id) is the rare exception, reserved for PII with no independent retention story from the owning BC's own erasure AND no cleanly derivable single id of its own (a genuine 1:N relationship where deriving one id per foreign parent would collide across siblings) — and even then the receiving BC still declares its own explicit `DropCipherKeyOn<ForeignEvent>` reacting to that Integration Event, never counting on the foreign BC's own drop silently covering it. Which BC declares and triggers a shared subject id's drop is always a real ownership decision, never left implicit.
- A business threshold intrinsic to the aggregate's own invariant (never an operational knob) is a `private const` on the aggregate — Domain carries no dependency injection, a container parameter is unreachable from inside a transition.

## Tests

### Conventions

#### Naming
- Aggregate: success `it*`. A genuine invariant violation (no business meaning on current state) is `itCannot*`, throwing. A re-entry that still matches the caller's intent is `itDoesNot*`, asserting no event recorded — never the reverse. A refusal worth recording as its own fact is `itRejects*`, asserting the dedicated rejection event — same name at the Application Handler layer when it exercises the same transition through `dispatch()`.
- Value Object: success `it*`, failure `itProtectsInvariants` (the violated condition lives in the test name or a data set label).
- A `<X>State`'s own boolean predicate, exercised by iterating every case in one test: `it{Predicate}` (mirrors the method name, e.g. `itIsActive` for `isActive()`) — never a trailing `OnlyWhen<CurrentCase>` naming today's exact case set as if it were the contract.

#### Fixtures
- A Value Object test sources its fixture values as plain, explicit literals — never random/generated — unless the field is genuinely UUID-shaped in real usage, or a plausible hand-typed value would itself risk reading as real business data.
- A Value Object that trims/normalizes its input proves that behavior once, through its own `equals()` test (one side plain, the other padded) — a dedicated normalization-only test duplicates that proof without catching anything new, so it's dropped in favor of the `equals()` case; the same reasoning drops a padded/whitespace dataset from the creation test's own accepted cases.
- An accepted value exactly at an invariant's boundary (a length/range ceiling or floor) is proven through the same creation test that already covers the plain case — an extra data set, never a second test method constructing the same VO again.
- A derived/formatted accessor asserted inside a parametrized creation test is recomputed directly from that same test's own input parameters — never passed in separately as an expected literal behind an optional parameter.
