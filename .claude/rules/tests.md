## Rules

**ALWAYS**
- Test methods carry the `#[Test]` attribute.
- Code is organized in three blocks separated by blank lines: `// Given`, `// When`, `// Then`. For an exception test, `// Then` (`expectException()`) comes before `// When`. The call under test is always assigned to a variable inside `// When` — `// Then` only asserts against already-computed values, never invokes the SUT inline inside an assertion.
- A Finder call repeated in the same test against the same entity, outside an explicit before/after comparison, reduces to a single call reused wherever its result is needed — never literally one call per distinct thing checked (the subject, a decoy, each item of a batch each still gets its own single call).
- A Repository call repeated in the same test against the same entity, outside an explicit before/after comparison, reduces to a single call reused wherever its result is needed — same reasoning as the Finder rule above, never literally one call per distinct thing checked. A test whose own name already names more than one Repository method as its subject (a round-trip test asserting both presence and content) is exempt for each method its name covers — that repetition is the named contract, not redundancy.
- A `// Given` block ends in exactly one `$this->store(...)` call, combining every aggregate it built. A second aggregate's construction referencing a first one's id never needs that first aggregate persisted first — the id is already known (generated before persistence), so nothing blocks building both and storing them together. A state-transition needed on a built aggregate before the test's own subject runs is expressed as a Test Factory modifier building the aggregate in its final state up front, never as a direct call on the aggregate between two separate `store()` calls. A second `store()` after `// Given` is only ever legitimate inside `// When`, when persisting again is itself the behavior under test (e.g. a Projector reacting to the newly persisted event). One `store()` call still orders its arguments deliberately when a built-in-final-state aggregate's own transition cascades an Integration Event whose Projector reaction writes into another passed aggregate's own row by reference (an `UPDATE` keyed by id, not the row's own creating `INSERT`) — that referenced aggregate goes first in the argument list, since the cascade only lands once its row already exists.
- A `// Given` combining a subject under test with a generic decoy ("other"/"others") declares the decoy first, the subject last — combined into one `store()` call, same order, spread argument last (PHP forbids a positional argument after one). A subject created after its decoy always sorts after it in a collection's own default order, so a mutant that drops a filter/lookup can't coincidentally return the subject instead of the decoy.
- Every Test Factory build is assigned to its own bare, descriptive local variable first, never an inline `X::new()->...->create()` passed straight into `store()` or a modifier chain — including a lone, single-item `store()` call.
- An identical construction (a `service(<X>::class)` resolution, a constraint instance reused across data sets) repeated across two or more call sites in the same test class is hoisted once instead of repeated — a property resolved in `setUp()` when the call sites are instance methods, a `private static` helper when they're static (a data provider). Exception: a Web test case, where `setUp()` runs before the test method's own `self::browser()`/`createClient()` call — resolving a service that early boots the kernel out of order (`LogicException: Booting the kernel before calling createClient()...`), so the repeated resolution stays inline there.
- Success and failure cases for the same behavior are grouped together, success first. A no-op success (`itIgnores*`) groups with the success side, before every `itFailsWhen*` — it never throws, so it stays on the non-throwing side of the split regardless of where its own guard sits in the real execution sequence.
- Multiple failure cases for the same behavior are ordered to mirror the sequence their guards actually run in the code under test — never insertion order, never alphabetical by exception name.
- A relational-operator comparison against a threshold (`<`/`<=`/`>`/`>=`, e.g. a window/retention policy's expiry check) is tested exactly at the boundary value, not only clearly-before/clearly-after — otherwise a mutant flipping the operator's inclusivity survives unnoticed. An exact-boundary case in a compound with more than one rule on the same value must satisfy every other rule too — verify first, drop the case if two rules conflict at that edge.
- Two or more related timestamps anywhere in the same test (a plain `TestCase`/`#[DataProvider]` included, not only the `AggregateRootTestCase`/`AbstractIntegrationTestCase` shapes below) are expressed as one local anchor plus `modify()` off it, never as separate hand-typed `\DateTimeImmutable` literals.

**NEVER**
- Mock an Aggregate or a Result object directly — build it through the matching Test Factory instead of a test double.
- Call `expects()` on a `createStub()` — a stub simulates a return value, a mock (`createMock()` + `expects()`) verifies a behavior.
- Suffix a variable with `Mock`/`Stub` — use the short class name (`$repository`) or the constructor argument's name when several dependencies share a type.
- Use a literal value that doesn't match the real field's format — a UUID-typed id gets a fake UUID (e.g. `Uuid::uuid7()->toString()`), not an arbitrary string.
- Hardcode another BC's vocabulary as a literal — use a generic/fake value instead.
- Wrap a Value Object's own `equals()` call in `assertTrue`/`assertFalse` as a shortcut for comparing structured data, when the test's actual subject is that data surviving a round-trip or crossing a boundary correctly (not the VO's own `equals()` implementation) — on failure it only reports `false` was not `true`, with no indication of which field diverged. Compare a primitive array of every field on both sides through `assertSame` instead, so a mismatch shows which one. `assertTrue($vo->equals($other))` stays correct where the VO's own `equals()` behavior genuinely is the test's subject (a dedicated equality test for that VO).
- Assert a closed vocabulary through the enum foreign to the layer under test — a Domain aggregate test (`given()`/`when()`/`then()`, a transition's guard) compares against `<X>State`; an Application/Infrastructure/DM test (a Finder `Result`, a Projector row, a webhook/API response) compares against `<X>Status` — the two never substitute for each other even where their case values currently coincide.

## Conventions

### Naming
- Method names: `it{Verb}*` — bare, no implementation detail. The verb is always active, mirroring the method it exercises (`itDelivers`, `itCancels`) — never passive (`itIsDelivered`).
- The test class already fixes the subject under test — a method name never repeats it as a noun. The same holds for a condition: a class already named after the one scenario its single test exercises doesn't restate that scenario in the method name either — it reduces to the bare verb.
- "On" names a reaction to an already-recorded fact (a Policy/Projector's own shape) — never reused elsewhere for an unrelated meaning (e.g. a gateway's own failure condition), since out of that context it misreads as the same reactive shape.
- An article ("a", "an", "the") is dropped wherever it precedes a noun. It stays only where dropping it would leave an adjective or relative clause with no noun left to attach to — reword instead of leaving it dangling.
- A quantifier ("Every", "Both", "All"...) never restates a completeness guarantee the architecture already provides — a batch operation that always acts on its full filtered collection by construction needs no quantifier, the plural noun alone already conveys the whole matching set. It stays legitimate to name an actual multi-condition business fact (a genuine AND/OR the system could satisfy incorrectly) that isn't already carried by a data provider's own case labels.
- A state/trigger condition always connects with "When" — never a synonym ("Once", "Yet", "After"...), whether the condition is a state, an elapsed duration, or an actor's action. The linking verb ("is", "was") inside that condition is dropped the same way as an article, once the subject noun it refers to is already gone — `WhenNotFound`, never `WhenIsNotFound` or `WhenOrderIsNotFound`.
- A negated need/requirement condition is phrased as the subject noun followed by postposed "Not" (`WhenRehashNotNeeded`), the same shape as `WhenNotFound` — never a preposed quantifier ("WhenNoRehashNeeded").
- "When" and "With"/"Without" never substitute for each other: "When" names a precondition already true of the system before the call (a state, an elapsed duration, a related record's own shape); "With"/"Without" names an argument or payload value the caller supplies on the call itself. A fact only ever readable off the system's own prior state, never off the call's input, stays "When" even if it superficially reads like a qualifier on the actor's action.
- A test's name covers exactly what it asserts, nothing more — an assertion outside that scope belongs in a separate test. The reverse also holds: one success case covers its full contract in a single test — never fragment it across near-duplicate tests replaying the same call.
- Failure naming: the qualifier reflects the exception the test expects — its own name already carries whether the failure is a business rule or a technical constraint. When the same exception can be thrown from more than one distinct trigger, the qualifier instead names that specific trigger/condition, so sibling tests stay distinguishable — never the bare exception name repeated identically across them.
- Data providers: `provide[Context]`, `#[DataProvider]` attribute, `yield` with a descriptive label.
- A hand-written test double is prefixed by its real role, never a blanket term: `Dummy` when it has zero behavior beyond satisfying a type, `Stub` when it returns a canned/configurable answer with no real logic, `Fake` when it's a genuinely working simplified implementation, `Spy` when the point is an interaction recorded for a later assertion. A class/enum used by a single test is declared at the bottom of that test file; one reused across two or more test files moves to a `Support/Doubles/` folder instead (scoped to the narrowest BC/subdomain all its callers share).
- A double for a vendor class is written only after checking that class's own constructor/API for a built-in substitution flag (a disable switch, an injectable client) — never hand-roll one already available. A Stub/Fake's canned output stays recognizably fake even under a technical constraint (fixed length, charset) — truncate/pad the existing pattern first, a real algorithm only once that can't satisfy it.

### Test Factory
- `<Aggregate>TestFactory extends Support\Factory\AbstractAggregateTestFactory`, one per aggregate, colocated at `tests/<Subdomain>/<Bc>/Support/Factory/` — the abstract base class itself lives at the repo-wide `tests/Support/Factory/`, never under a specific BC or under `Shared`, since it mirrors nothing in `src/` and every BC's own Test Factory depends on it.
- `defaults()` returns attributes already typed as the Value Object each carries downstream (never the primitive an outside caller supplies) — Faker-backed (`Support\SeededFaker::get()`, called directly — no factory-level wrapper), except the aggregate's own creation-timestamp attribute, which calls `Support\ClockSequence::next(): \DateTimeImmutable` directly instead — a shared sequence, reset before every test, that ticks forward on each call. This keeps that attribute's own value monotonically increasing with real construction order across every Test Factory and aggregate, root-generated id or derived id alike, so a Finder's default `id`-based order and a `createdAt`-based order never disagree on a list built through `many(n)` or through separate `create()` calls. `build()` takes no parameter — it reads each field through `$this->attribute('key')` and calls the aggregate's own named factory with named arguments (`Order::place(id: $this->attribute('id'), ...)`) — never a bare constructor, never a repeated `Assert::` block reconstructing what the generic `attribute()` accessor's own per-key return type already guarantees. A key the aggregate derives from another rather than accepting directly (an id built via a `for<Concept>()` factory off another key already resolved) is computed from `$this->attribute('key')` inline in the `Order::place(...)` call, never stored as its own `defaults()` entry.
- `with*()` methods keep their own parameter primitive for calling-test ergonomics, converting to the stored Value Object internally before merging — `withId(string $id)` stores `SomeId::fromString($id)`, never the raw string. They return a new instance via `$this->withAttributes(['key' => $value])` — a partial override, never `array_merge($this->attributes, [...])` first (`withAttributes()` on the base class already merges onto the current attributes) and never `static::new(...)` directly: `$attributes` is `readonly`, so a fresh instance is unavoidable, but `withAttributes()` also carries the already-chained modifiers over to it; `static::new()` alone would silently drop them if a `with*()` is chained after a modifier. A state-transition modifier (e.g. `cancelled()`) uses `withModifier()` and calls the real aggregate method. It wraps exactly one transition — never another modifier internally to reach its own starting state — so modifiers stay chainable in the same order as the aggregate's real lifecycle (`dispatched()->tracked('X')->delivered()`, not a `delivered()` that redundantly dispatches on its own).
- `defaults()` holds exactly the attributes `build()` consumes to construct the Aggregate — nothing else. Every one of its keys, with no exception (an `id`, a construction timestamp, anything), gets a matching `with<Key>()`, declared in the same order as `defaults()`'s own keys — whether or not a test currently needs to override it. A required attribute with no `defaults()` entry (e.g. `hasher`, declared as an optional key on the class's own `Attributes` shape, asserted via its private accessor) still gets its `with*()`, placed after the `defaults()`-backed ones.
- Every state-transition method the aggregate exposes gets a matching modifier, declared in the same order as the aggregate's own methods — a transition with no modifier is a gap, not an intentional omission.
- A modifier's own argument (a timestamp, an amount, a reference, a free-text label/reason) is never hardcoded inline — always an overridable parameter. A value with genuine fixed business meaning (a bool, a specific enum case) is declared directly as the parameter's default. A value computed once per call (a method/static call, e.g. `Clock::get()->now()`, or an arbitrary/no-fixed-meaning string with no business meaning of its own) is `?Type $x = null` plus `$x ??= <call>` — an arbitrary identifier/label resolves via Faker in the modifier's own body the same way a timestamp resolves via the clock, never a hardcoded literal that can collide across fixtures sharing that same default. Its closure keeps reading that same local variable directly (`static fn ($aggregate) => $aggregate->manifest(TrackingReference::fromString($trackingReference), ...)`) rather than re-reading it off the resolved-attributes array — the local variable and the stored attribute are set from the identical expression in the same method, so re-reading buys no real safety and an optional key read through a raw array offset (`$attrs['trackingReference']`) only trips PHPStan's `offsetAccess.notFound` for no benefit. A modifier needing a key `defaults()` already supplies (e.g. `customerId` for a self-authorization check) receives it through its own resolved-attributes parameter instead (`withModifier`'s callable takes the built Aggregate and the fully-merged attributes: `static function (Order $order, array $attributes) { ... }`) — never `$this->attributes` read before the merge, which is a caller-supplied partial and would force that key to look optional on the class's own `Attributes` shape when `build()`'s contract actually requires it. A required key with no `defaults()` entry at all (a collaborator with no fake default, e.g. `hasher`) is the one legitimate case left reading `$this->attribute()` directly inside a private typed accessor (`Assert::isInstanceOf()`), called from both `build()` and every modifier that needs it — one real runtime check, reused, never a `@var`/`Assert` block repeated inline at each call site.
- A modifier that generates its own arbitrary value (a tracking reference, a rejection reason) additionally stores it via `$this->withAttributes(['key' => $value])` before registering itself, declaring that key `?` (optional) on the class's own `Attributes` shape — never in `defaults()`, since it doesn't exist before that modifier runs. This is what makes the value retrievable afterward through the public `attribute()` accessor (see below), without the modifier's own closure needing to read it back that way.
- `AbstractAggregateTestFactory::attribute(string $name): mixed` is generically typed (`@template TName of key-of<TAttributes>` / `@return TAttributes[TName]`) so a call site gets the exact per-key type back with no `@var`/cast — `$factory->attribute('id')` infers as the id Value Object, `$factory->attribute('trackingReference')` as the optional key's own type. It reads the same resolved (`defaults()` + overrides) bag `build()` itself reads, recomputed fresh on every `create()` call (a `many(n)` broadcast must still get a distinct random id per item; the resolved bag is never reused across two `create()` calls on the same instance) and cached only between the end of one `create()` and the next — so it always reflects exactly what the most recent `create()` actually built.
- A value already readable off a built Aggregate through a real accessor (its own id, any other exposed field) is read at the call site through that property — never pre-declared as a separate variable threaded through both the `with*()` call and the later usage, which creates a second, driftable source of truth for the same value. A `with*()` override on the Aggregate's own identity exists for the opposite case: forcing/sharing a specific, predetermined value (e.g. `CustomerTestFactory::withId($identity->id->toString())`, matching another already-built Aggregate's id) — not for "just need some value, read it back afterward". A value a modifier generated but the Aggregate exposes no accessor for (it earns one only by the usual field-accessor rule, never for a test's own convenience) is read back through `$factory->attribute('key')` instead — the test keeps the factory itself in a local variable (`$factory = X::new()->manifested(); $shipment = $factory->create();`) precisely so `attribute()` stays reachable after `create()`.
- `// Given` (state setup) is a factory method call; `// When` (behavior under test) is a direct call on the Aggregate returned by `create()`.
- `create()` returns one Aggregate; `new()->many(n)->create()` returns `list<Aggregate>` through `Support\Factory\AggregateListTestFactory` — `many(n)` broadcasts one shared attribute override to every item, so it can't vary a per-item field genuinely tied to a `with*()` call (e.g. a sort-key label) — the creation-timestamp attribute is exempt from this limitation, since it's computed fresh per item through `defaults()` rather than broadcast.
- A Test Factory never persists — `create()`/`attribute()` only ever build or read back in-memory state. Persisting is always `$this->store(...)` (`Support\TestCase\EventSourcingTrait`, see CQRS/container below), called on the built Aggregate(s) after `create()`.
- Two branches in the same test that would otherwise repeat an identical modifier prefix of 3 or more calls before diverging on one trailing call (or one call's argument) share that prefix as a single instance instead, reassigned under the subject's own variable name as it advances — a Test Factory's immutability guarantees the earlier reference stays untouched once a later call branches off it. Never collapse the prefix when either branch's own modifier argument differs at the shared depth (that difference is real signal, not duplication), nor when the second branch is a decoy deliberately left at its own baseline (no modifiers at all) rather than mirroring the subject's progression — merging that case would make the decoy start resembling the subject instead of staying an untouched control.

### Test doubles
- An integration test's double strategy follows its own subject, never a collaborator's cost or determinism. A storage-boundary test (Repository/Finder/Projector) has its own round-trip to storage as sole subject: a service collaborator needed merely to build a valid Aggregate through its Test Factory is doubled, deterministically — its own correctness belongs to that service's own dedicated test. A Value Object carried across that same boundary is never doubled this way, it's the data under test, not a service. A use-case test (a Command/Query Handler, or an Application port exercised directly by a Delivery Mechanism) has the whole orchestration as its subject instead: every in-process collaborator is wired for real; only a boundary actually leaving the process (a vendor call, a transport) gets doubled there.

### Event Sourcing (`Patchlevel\EventSourcing\PhpUnit\Test\AggregateRootTestCase`)
- `given(...events)->when(fn (Aggregate $a) => ...)->then(...expectedEvents)` — the standard shape for an aggregate unit test.
- `expectsException(...)` replaces `then(...)` for a failure case.
- Every timestamp in the test is expressed as `$now->modify('+1 day')`/`modify('-2 hours')` off one local anchor, never a separate hand-typed `\DateTimeImmutable` literal per fixture — this test never touches a Test Factory or the container, so the anchor stays a fixed local literal, never `Clock::get()->now()` itself. Its value matches the suite-wide frozen instant (`$now = new \DateTimeImmutable('2026-01-01T00:00:00+00:00')`, the same instant `ClockExtension` freezes `Clock::get()->now()` to) — a different, arbitrary "today" per test file reads as two disconnected eras across the same suite for no reason, even though nothing here actually calls the frozen clock. Each `modify()` delta itself must read as a plausible real-world gap for what it represents (a shipment manifested hours after preparation, never open-endedly far apart) — a boundary case straddles its threshold by a small, deliberate margin on each side, not an arbitrary offset picked for arithmetic convenience.

### CQRS / container (`Support\AbstractIntegrationTestCase`)
- `dispatch()` sends a Command to the Command bus; `ask()` runs a Query and returns its result.
- `service()` resolves a service from the container with a type assertion on the given class/interface. `serviceAs()` resolves a service whose container ID differs from the PHP type it's expected to be (e.g. a Doctrine alias).
- A Policy or Processor is exercised directly — construct/fetch it and invoke it with the event it subscribes to — rather than relying on a running subscription worker in the test suite.
- `store()` persists and triggers the `publisher` then `projector` groups (never the `#[Policy]`/`#[Processor]` side effects).
- `publishedEventOf(string $eventClass)` returns the persisted event of that type, scanning the whole store.
- A check against "now" that's a passive, non-reactive comparison (an `expiresAt`/TTL field read at query time, no `#[Policy]`/cron triggered by the passage of time) is tested with a deliberately far past/future static date on the Test Factory — real wall-clock time, no clock involved. A check whose SUT holds an injected `Psr\Clock\ClockInterface` for behavior that genuinely reacts to time passing, or needs a precise boundary, reads `Clock::get()->now()` as its anchor, same as everywhere else — the suite-wide `ClockExtension` already freezes `Symfony\Component\Clock\Clock`'s global singleton to one fixed instant before any test runs, and the container's own `clock` service has no inner clock of its own, so it already proxies that same frozen singleton. A test never overrides the container's `clock` service with its own `MockClock` instance — that creates a second, independent clock diverging from `Clock::get()->now()`, which every Test Factory default already reads from.
- Every fixture timestamp in a test is expressed as `$now->modify('-2 hours')`/`modify('-3 days')` off that one frozen `Clock::get()->now()` anchor — never a second, independently hand-typed `\DateTimeImmutable` literal per fixture. The delta itself must read as a plausible real-world gap for what it represents (an order refunded hours or days after capture, never open-endedly far apart) — a `stuck`/`fresh` pair straddles the threshold by a small, deliberate margin on each side, not an arbitrary date picked for arithmetic convenience.
