## Source

### Rules

**ALWAYS**
- Rehydrating a date from the database: `new \DateTimeImmutable($value, new \DateTimeZone('UTC'))` — an explicit timezone, otherwise the behavior silently depends on the server's local timezone.
- An Event Store repository's `load()` catches `AggregateNotFound` and re-throws the BC's own `<Aggregate>NotFoundException` — otherwise a vendor exception leaks out as a raw 500 instead of a mapped domain failure.
- A Projector extends `AbstractDbalProjector` — outside that base class it isn't in the `projector` group and its schema is never created.
- A Finder reads `from(<Projector>::TABLE)`, never a re-declared table-name literal — otherwise it silently drifts if the projector's table changes.
- Native `\assert()` narrows a value already guaranteed correct by the calling code, never external/user input. `Webmozart\Assert` stays reserved for a real invariant that must hold in production and throw a catchable exception.

**NEVER**
- Use a raw `HttpClientInterface` outside `Shared\Infrastructure\Gateway`.

### Conventions
- `Infrastructure/`'s top-level folders name a technical concern (`Persistence/`, `Monitoring/`, `Security/`...), never a vendor mechanism — the mechanism stays visible in the class name's own suffix instead, not the path.
- Event Store repository: `Persistence/EventStore/Repository/<Agg>Repository`, `final readonly`, implements `<Agg>RepositoryInterface`; injects `#[Autowire(service: 'event_sourcing.<subdomain>.<bc>.<aggregate>.repository')] Repository<Agg> $repository`; `has()` delegates as-is, `load()` catches `AggregateNotFound` and re-throws its own `<Agg>NotFoundException`; `save()` catches `AggregateAlreadyExists` and re-throws its own `<Agg>AlreadyExistsException` the same way — every aggregate's identity can collide at the event-store level regardless of whether the BC currently relies on it as a business guard, so the adapter always encapsulates it, never a bare delegate.
- Projector: `#[Projector('<subdomain>.<bc>.project_<name>')] final readonly Dbal<X>Projector extends AbstractDbalProjector` (e.g. `sales.order.project_orders`), a `public const string TABLE`, one `#[Subscribe(<Event>::class)] on<Event>()` method per event, and `configureSchema()`. No `_on_<trigger>` clause — a Projector reacts to many events feeding one materialization, so no single trigger to name. A status/type column stores the Application `<X>Status` enum's value, never the Domain `<X>State` enum's — the projection is a read model consumed through a Finder/DM, the same boundary that already forbids the Domain enum crossing into `Application/`/`dm.md`'s exposition surface; deriving the column value from `<X>State` instead couples the stored/filterable value to a representation Domain never promises to keep in sync with `<X>Status`.
- One projection per materialization shape (one table, named after what it materializes); as many Finders as there are read axes over that table. A new Projector is warranted only when the access shape itself differs (key, granularity, denormalization) — never just for a new DTO.
- `IntegrationEventAppender` (`Shared/Infrastructure/Persistence/EventStore/Appender/`) is the only piece touching the Store for Integration Events, implementing `Shared\Application\IntegrationEvent\IntegrationEventPublisherInterface`'s `publish()`: `Webmozart\Assert::subclassOf($aggregateClass, AggregateRootMetadataAware::class, ...)`, then derives the stream from `<aggregateClass>::metadata()->streamName($id)` with `'integration.'` prepended.
- DBAL Finder: `Dbal<X>Finder extends AbstractDbalFinder<Result>`, `final`, never `readonly` (`$queryBuilder` is clone-reassigned) — a collection/filterable read extends `AbstractDbalCollectionFinder` instead (itself an `AbstractDbalFinder`), immutable, consumed via `foreach`/`count()`, never a terminal `get()`. A single-shot lookup is named `ofX()` when absence is an anomaly: it throws its `<X>ResultNotFoundException` (mapped in `config/packages/exceptions.php`). It's `ofXOrNull(): ?Result` instead when absence is a valid outcome for at least one caller.
- A filter binding more than one literal value uses `QueryBuilder::createNamedParameter()` at each call site instead of a hand-invented `:name` plus a matching `setParameter()` call — it returns the placeholder to embed directly in the expression, and the same value reused across several sub-conditions (e.g. one cutoff compared against several columns) calls it once and reuses the returned placeholder, never one invented name per sub-condition for what is the same bound value.
- A collection Finder's dynamic filter is `by<Concept>(string $value): static` — a single equality parameter by default. It becomes variadic (`by<Concept>(string ...$values): static`, `IN` instead of `=`) only once a real caller actually needs to filter by more than one value at a time — never speculatively, since a single-value `IN` optimizes identically to `=` and an unused variadic parameter is dead flexibility. A non-equality operator appends one suffix from this exhaustive list, never an improvised one: `Not` (`!=`/`NOT IN`), `Containing`/`StartingWith`/`EndingWith` (`LIKE`), `After`/`GreaterThan` and `Before`/`LessThan` (`>`/`<`, date vs numeric field), `AfterOrEqual`/`GreaterThanOrEqual` and `BeforeOrEqual`/`LessThanOrEqual` (`>=`/`<=`). `Not` always precedes any other suffix when composed (`byNameNotContaining`, never the reverse) and never attaches to a bare predicate. A boolean or nullity check with one meaningful polarity is a bare nullary predicate instead (`active()`, `untracked()`) — the opposite polarity, if ever needed, gets its own separately-named method, never a `Not` suffix on this one. An `OR` across exactly two columns fuses both names in alphabetical order (`byEmailOrName`, not `byNameOrEmail`); across three or more, abandon concatenation for an intent-named method instead (`matching(string $term)`). Sorting is `sortedBy<Field>(): static` — same chainable shape, but it orders rather than narrows.
- One `Dbal<X>Finder` per materialization shape (same table, same `Result`) — a new implementation is warranted only when the shape itself differs, same threshold as the Projector rule above.
- A collection Finder's `buildBaseQuery()` ends on an explicit `orderBy(<its own id column>, 'ASC')` — a bare `SELECT` with no order gives pagination no stable, deterministic slice across two calls. Since every aggregate id is a UUIDv7 (time-ordered), ordering by id alone already gives a chronologically-consistent default with no dedicated column needed. A `sortedByX()` method is introduced only once a real exposition need calls for a different order.
- Reaching a vendor is two levels, both named after the business concept, never a generic `Gateway/` bucket: the port is `<Bc>/Application/<Concept>/<X>GatewayInterface`, its adapter `<Bc>/Infrastructure/<Concept>/<Vendor>/<Vendor><X>Gateway implements <X>GatewayInterface`. That same folder is the only holder of the scoped HTTP client, `<Vendor>Client` — speaks the vendor's protocol, turns transport/decoding failures into `<Vendor>ClientException`; the adapter holds no client of its own, calls that one and maps the payload, raising the same typed exception on a response it cannot read. The client moves to `Shared/Infrastructure/Gateway/<Vendor>/` only once a second BC actually consumes the same vendor, never in anticipation of one. The concept segment names each Bounded Context's own real Ubiquitous Language term for that integration — a process noun in one BC and a role noun in another are both legitimate when that's genuinely how each domain's own practitioners speak, never forced onto one shared grammatical axis across BCs for symmetry's sake alone.
- A composite projection subscribes to its own Domain Events plus a foreign BC's Integration Events — never a foreign Domain Event, never another BC's projection. It reads the foreign stream directly at fold time to denormalize onto its own table — `Persistence/Projection/Reducer/Stream<X>Reducer`, reading via `Store::load(new Criteria(new StreamCriterion($streamId)))`, folded with `Patchlevel\EventSourcing\Message\Reducer` (`initState()`/`when()`/`reduce()`), converted to a small immutable DTO. Each foreign attribute that can change over time gets its own `#[Subscribe(<IntegrationEvent>)]` fan-out method, materialized as a nullable column. A Policy mutates (dispatches a Command); a Reducer only reads.
- Every folder under `Persistence/` names the *role* — `Repository/`, `Appender/`, `Projection/Reducer/` — never a bare vendor mechanism name; the `Stream` prefix on a class distinguishes a fold over the event stream from a sibling case built over already-materialized data, and comes first (`Stream<X>Reducer`, matching `Dbal<X>Finder`/`<Vendor><X>Gateway`'s own mechanism-first ordering), never as an infix.
- A cross-BC provider contract, or several same-BC implementations of one strategy interface a router delegates to, is wired as a tagged iterator — never `#[AutoconfigureTag]`/`#[AutowireIterator]` inline attributes, which put an Application-layer class under a direct dependency on an Infrastructure vendor token. The interface itself carries no attribute; the owning `config/services/<subdomain>.php` tags every implementation (`$services->instanceof(<X>Interface::class)->tag('<tag>')`) and binds the consumer's constructor arg (`$services->get(<Consumer>::class)->arg('$x', tagged_iterator('<tag>'))`). The `instanceof()` call must be declared *before* `SubdomainServiceLoader::load()` in that same file — declared after, the tag silently never applies to any already-loaded definition.
- A cross-BC gate on the bus (a fact one BC owns that any Command/Query across every BC must respect) is a Messenger middleware living in the owning BC's own `Infrastructure/<Concern>/`, registered in `config/packages/messenger.php`'s `middleware` array on whichever bus needs it, reading that BC's own Finder directly — never a `Shared`-owned middleware reaching into a business BC. The message opts in through a pure marker interface in `Shared\Application\Command\`/`Query\` naming the field the gate checks — a zero-field contract only, so a Command/Query implementing it stays within its own "native types only" boundary rule.
- A business time threshold is a container parameter under `config/services/<subdomain>.php` (`<subdomain>.<x>_window_days` looking back, `<subdomain>.<x>_days_ahead` looking forward), injected via `#[Autowire(param:)]` into the service that computes the date — never a literal in code.
- A critical section whose duplicate execution would trigger a real external side effect (not just re-checking an aggregate's own guard) is wrapped in `Shared\Infrastructure\Locking\LockingTrait::withLock()`, keyed by a resource name scoped to the specific entity being protected. Applied via a `#[AsDecorator]` around the port it protects, never inlined into that port's own implementation, so the port itself stays substitutable and free of locking concerns. The lock's own failure (`LockNotAcquiredException`) is caught at that same decorator boundary and re-thrown as the caller-facing business exception — it stays unmapped in `config/packages/exceptions.php` so a caller that forgets to catch it surfaces as a raw 500 instead of a silently swallowed refusal.

## Tests

### Conventions

#### Naming
- Repository: success `it*`, failure `itThrowsWhen*`.
- Projector: `itProjectsOn*` for every reaction that inserts a new row or mutates an already-projected one in place (no dedicated failure shape). A reaction whose own assertion proves the row is gone (a `fetchRow()` returning nothing/false), not merely updated, is `itRemovesOn*` instead — the verb states what the row's own final state actually is, never a euphemism for a real deletion. No noun between the verb and "On" — the event named after it already carries what's affected.
- Finder: an exact lookup that throws when absent is `itGets*`, failure `itThrowsWhen*`. A lookup that stays nullable instead is named `itFinds*`, covering both outcomes in one method — for that one, absence is a valid result, not a failure, so `itFinds*` never takes the `itThrowsWhen*` shape. A collection read (iterate/filter/paginate) is `itLists*`/`itFilters*By*`/`itPaginates*` — `itGets*`/`itFinds*` are reserved for a single-shot lookup, never a collection scan.

#### Structure
- A Projector test asserts DB state through a `private fetchRow(string $id): array|false` helper — never an inline `SELECT`.
- A Projector test exercising an UPDATE (a reaction on an aggregate that already has a projected row) stores a second, unrelated row (different id and a different value on the field the UPDATE writes) alongside the one under test, and asserts that row stayed untouched — a single-row dataset can't distinguish "the right row was targeted" from "whatever row existed got updated", so a mutant removing the UPDATE's WHERE/identifying criteria entirely survives unnoticed.

#### Test doubles
- An Application-level test (a Policy/Handler exercising the port) doubles the port interface directly, no HTTP involved. Only the dedicated Infrastructure test for the concrete adapter doubles the vendor client instead, to exercise that adapter's own HTTP↔Domain mapping (payload serialization, error mapping to its own client exception).
